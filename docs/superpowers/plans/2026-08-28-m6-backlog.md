## 建议修（M6）

1. **readLockStatus 内部竞态兜底**（终审新发现 I-1）：stale-lock.ts 的 readdirSync/statSync 在 existsSync 之后被并发删除时 ENOENT 裸抛——backup.run() 的活锁检查段会绕过所有恢复分支（serve 已杀、state=stopped、502）。修法：读失败按 absent/stale 处理，或 run() 该段包 try 走中止分支（与活锁中止的 best-effort 拉回对称）。
2. killServe 检查 taskkill 退出码（返回 pid 语义从"已下令"变"验尸"）——残余窗口：进程未死且锁 pid 匹配 → 不一致快照（概率极低，数据安全方向）。
3. backupRunning 容忍的逃生口：连续 N 次 status 失败后放弃容忍置 offline（防"备份中面板死掉 → online 永真"）。
4. M-1：/api/status 的 backupRunning 字段补直接断言（注入 backup 的 true 路径 + 无注入 false 路径）。
5. M-2：prune() rmSync 失败包 try（错误信息友好化）；M-3：活锁中止用例断言 best-effort start() 被调用。
6. Agents 页时间列统一 toLocaleString（与 Backup 页一致）；retention 测试细化（toBe(5)/toBe(1) 区分回退与钳制）。
